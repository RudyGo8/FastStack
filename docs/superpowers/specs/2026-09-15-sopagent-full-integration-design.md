# SopAgent 完整融合与全用户授权设计

## 背景

SopFast 以 FastStack 为脚手架，已经迁入 SopAgent 的后端模块、7 个前端页面和菜单种子，但当前融合并不完整：

- 现有数据库中的三个内置角色均未关联任何 `module_sop:*` 菜单权限；普通用户登录后看不到 S&OP 模块。
- `InitializeData` 对已有数据的表执行整表跳过，修改 `sys_menu.json` 不会更新存量数据库。
- `sys_role_menus.json` 使用固定菜单 ID；实际数据库的 S&OP 菜单 ID 由递归插入顺序生成，固定 ID 已经指向其他菜单。
- 原 SopAgent 的 7 个页面合计约 3679 行，当前融合页面约 923 行。数据看板、报告、知识库和聊天等页面只保留了简化版本，多个原有业务视图和交互缺失。

本次目标是在不清空数据库、不破坏现有 FastStack 系统功能的前提下，恢复 SopAgent 已有的业务能力，并让所有已登录用户都可使用完整 S&OP 模块。

## 已确认决策

1. 沿用 FastStack 的统一登录、用户、角色、动态路由和操作审计机制。
2. 前端继续使用 Vue 3、TypeScript、Element Plus 与脚手架布局，不嵌入或并行运行旧前端。
3. 所有已登录用户具有 S&OP 全部菜单和接口权限，包括查询、导入、同步、上传、删除、生成快照、导出和流式问答。
4. 修复必须兼容已有数据库，不能要求清库重建。
5. 业务页面只展示真实接口数据；缺失值展示为空态，不使用演示数据代替生产事实。

## 方案选择

采用“声明式增量同步 + 语义级页面恢复”。

- 不采用清库重建：虽然能重新导入种子，但会丢失用户和已有业务数据，且下次菜单变更仍会复发。
- 不采用移除接口权限校验：这会绕开脚手架 RBAC，无法留下清晰的权限模型，也不能解决动态菜单不可见问题。
- 不直接复制旧前端：旧页面的样式体系、认证和接口封装与 FastStack 不兼容。恢复业务语义和交互，但按当前组件体系实现。

## 权限与菜单同步

### S&OP 菜单声明

保留一份稳定的 S&OP 菜单树声明，包含：

- 目录：S&OP 分析。
- 页面：数据看板、数据中心、知识库、智能问答、指标分析、会议报告、市场热点。
- 操作权限：数据查询/导入/同步、文档查询/上传/删除、聊天查询/流式问答/删除、报告查询/生成/导出。

菜单节点不得依赖数据库自增 ID。目录和页面优先用稳定的 `route_name` 定位，按钮用 `permission` 定位；父子关系使用同步后得到的真实 ID 建立。

### 幂等增量同步

应用初始化时，在通用基础种子导入之后执行专用 S&OP 同步：

1. 查询稳定键对应的现有菜单。
2. 缺失则创建；存在则更新名称、路径、组件、图标、顺序、状态和父节点等受管字段。
3. 不删除 S&OP 树之外的任何菜单，不重写其他模块配置。
4. 收集同步后完整 S&OP 子树的真实菜单 ID。
5. 将这些 ID 追加到所有未删除角色的菜单关联中；已有关系保持不变，重复执行不产生重复行。

以后创建的新角色也必须自动获得 S&OP 菜单。实现方式是在角色创建服务的既有流程中追加 S&OP 菜单 ID，而不是使用固定 ID 的静态 JSON。角色权限被管理员重新保存时，同样保留 S&OP 必选权限，确保“所有用户开放”不会被后续角色编辑撤销。

### 接口授权

后端控制器继续使用现有 `AuthPermission`，不改成匿名接口。所有角色都获得相应 `module_sop:*` 权限，因此：

- 未登录请求仍返回认证错误。
- 任意有效登录用户都能通过所有 S&OP 接口权限检查。
- 登录令牌中已缓存旧权限的用户需要重新登录；同步完成后可主动清理相关认证缓存，避免长期等待令牌过期。

## 后端融合审计

以原 SopAgent 的 API、领域服务和测试为基准，建立逐项映射表，检查当前模块是否完整迁入：

- 数据源状态、SPU 搜索、维度选项和一期报告查询。
- SPU、销售、激活、预测 Excel 导入与企业数仓同步。
- 文档列表、单文件/批量上传、切片信息和删除。
- 会话列表、消息读取、流式问答和会话删除。
- 快照生成、列表、详情、最新快照和 Word 导出。
- RAG、Milvus、MCP、缓存、调度器和同步数据库生命周期。

优先复用当前已迁移的领域服务。只有页面恢复所需且原项目确实存在、当前模块遗漏的接口才新增；不创造本次范围外的新业务能力。所有同步数据库操作从异步控制器调用时继续隔离在线程执行，避免阻塞事件循环。

## 前端功能恢复

公共计算与展示逻辑从大页面中提取为可测试的 TypeScript 工具，并迁移原项目已有测试语义，包括缺失值不回退到样例数据、状态标签、预测校验汇总、知识库指标、趋势数据集和渠道预测矩阵。

### 数据看板

- 数据就绪状态、核心指标和最近快照。
- 历史出库/激活与未来 AI/提报预测趋势图。
- 未来六个月分渠道提报预测对比矩阵。
- 数据为空或部分就绪时显示明确状态，不伪造指标。

### 数据中心

- 九类数据域同步状态、最新业务日期、记录数和备注。
- 企业数仓一键同步与各类 Excel 导入。
- SPU 品类主数据字典。
- 预测校验口径、会前快照策略与快照历史。
- 操作完成后统一刷新状态，并展示后端返回的部分成功或失败原因。

### 知识库

- 文档数、切片数和索引状态。
- 单文件/批量上传、文档列表、刷新和删除。
- 恢复文档切片查看；若当前后端缺少切片查询，则补充基于已持久化父切片数据的只读接口。
- 文件类型、大小、时间、处理状态和错误信息均来自真实数据。

### 智能问答

- 会话列表、新建、切换和删除。
- SSE 增量内容解析、取消/异常状态和自动滚动。
- Markdown 安全渲染、代码高亮和结构化工具执行信息。
- 会话严格按当前登录用户名隔离。

### 指标分析

- SPU 搜索以及区域、渠道、组织等维度筛选。
- 历史与预测趋势图。
- 预测校验汇总、明细、偏差等级、规则版本和归因证据。
- 当前筛选 SPU 的 Word 报告导出。

### 会议报告

- 报告就绪状态、核心指标、材料列表和快照历史。
- 历史/预测趋势、渠道矩阵、差异清单。
- 产销协同事实摘要与待决事项。
- 生成快照、查看快照详情及导出 Word。

### 市场热点

- 恢复原项目的能力说明、接入状态和展示原则。
- 外部数据源未配置时保持真实空态；不注入虚构热点。
- 数据源接入后展示后端返回的可审计内容。

## 数据流与错误处理

页面通过 FastStack 的统一请求封装携带令牌，请求 `/api/v1/sop/*`。普通 JSON 接口继续使用统一响应结构；文件下载和 SSE 保留原始响应类型。

错误处理遵循以下原则：

- 权限同步失败导致用户仍不可用时，应用启动失败并留下明确日志，避免静默启动成半可用状态。
- 单个外部依赖（源数仓、Milvus、模型、MCP）不可用时，只降级对应功能，并在页面显示具体状态。
- 批量导入和同步保留部分成功明细，不把部分失败误报为成功。
- 页面切换或组件卸载时释放图表实例和流式请求，避免重复监听与内存泄漏。

## 测试策略

严格按测试先行实现。

### 后端自动化测试

- 空库可创建完整 S&OP 菜单树且父子关系正确。
- 存量库只补充/更新 S&OP 节点，不改变其他菜单。
- 连续同步两次不产生重复菜单和角色关系。
- 所有现有角色同步后包含完整 S&OP 权限。
- 新建角色自动获得完整 S&OP 权限；重新保存角色授权不能移除这些必选权限。
- 普通 `user` 身份可访问每一种 S&OP 权限保护接口，匿名身份仍被拒绝。
- 原 SopAgent 领域测试与路由测试继续通过。

### 前端自动化测试

- 迁移原 `presentation` 与 `reportMetrics` 的行为测试。
- 覆盖趋势数据集、渠道矩阵、缺失值、零值和部分就绪状态。
- 覆盖 SSE 分片解析、结束、错误和取消。
- 对 7 个动态页面做基础挂载/构建验证。

### 联调验收

1. 在已有数据库上重启后端，不删除 volume。
2. 分别使用 `super`、`admin`、`user` 登录，确认 7 个菜单均可见。
3. 用普通 `user` 完成查询、导入、同步、上传、删除、聊天、快照生成和导出操作。
4. 走查上传文档到问答、数据导入到分析、快照生成到报告导出的三条主链路。
5. 执行后端测试、前端测试、类型检查和生产构建。

## 非目标

- 不重构 FastStack 的全局 RBAC 模型。
- 不迁回 SopAgent 独立用户表或认证接口。
- 不接入新的市场数据供应商。
- 不填充虚构业务数据，不修改已有真实业务记录。
- 不顺带调整 S&OP 之外的菜单、角色和页面。

## 完成标准

- 存量和新建角色都拥有完整 S&OP 权限，所有有效用户均可使用所有 S&OP 操作。
- 7 个页面恢复原 SopAgent 的业务信息结构和核心交互，同时符合 FastStack 页面体系。
- 原项目已有后端业务测试与迁移后的前端逻辑测试通过。
- 三条端到端主链路可由普通用户完成。
- 重启应用和重复执行同步不会产生重复数据或破坏现有配置。
