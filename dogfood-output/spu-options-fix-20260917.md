# SPU总数与候选列表不一致修复

## 根因与数据核验

管理卡片查询全部启用、非seed-demo的SPU，返回31个；工作台初始化却固定搜索C，并最多加载20项。目前包含C的型号共11个，另20个因初始搜索条件而未列出。清空搜索时原代码直接return，也无法恢复全量候选。

只读核对了真实数仓提报预测表与业务SPU主表：双方去重SPU集合均为31，集合差异为0。实际认证API不带搜索词返回31个候选，总数接口也是31。因此这次名单缺失发生在前端默认加载条件。

## 已修改

- 初始加载不带关键词，候选上限从20调整为API现有上限500；当前31个全部返回。
- 清空关键词会重新加载完整候选，而不是跳过请求。
- 保留当前选中SPU；首次默认仍优先C416（若不存在则选首个可用项）。
- 工作台刷新或重新激活时重读候选列表和管理总数，使新同步的SPU可见。
- 会议报告的默认SPU加载同样改为无关键词完整列表。

## 数据中心同步方式

企业数仓只读连接读取以下固定来源：

1. 从dwd_sales_forecast_import去重读取SPU，按编码新增/更新业务SPU主表和直接映射。
2. 同表读取真实正数提报预测值，并规范化预测年月。
3. 通过产品事件、销售出库单、物料SPU与部门链路提取出库事实：按销售出库单日期归属月份，按SN去重。
4. 从设备与产品激活记录提取真实激活事实，按激活日期归属月份。
5. 整批替换BIG_DATA_DW名下的预测、出库、激活事实并记录来源批次；其他来源事实不在这个替换范围。SPU主数据采用新增/更新模式。
6. 在同一事务生成该批次报告快照；成功一次提交，异常回滚，通过同步锁防止重叠批次。

工作台刷新/会议报告刷新和数据中心按钮均能触发此固定数仓流程。现有夜间任务仅对业务库已同步事实生成快照，不会自动读取数仓新数据。页面显示最后来源同步时点。

管理中的31个SPU范围来自提报预测表，不等于全公司物料主库的总量。未经新增产品主库来源，不能据此宣称覆盖全公司全部型号。

## 验证

- 初始完整31个、清空搜索恢复完整列表两项回归先失败，修复后通过。
- 工作台/会议报告/共享统计共31项前端测试通过。
- 实际认证API候选31个，总数31个；真实业务库与数仓SPU集合一致。
- 浏览器实际打开SPU下拉框显示31候选项；搜索AT1200显示两个匹配项，清空后恢复31项，管理总数仍为31，当前选择仍为C416。
- [下拉框页面证据](spu-options-all-20260917.png)。
